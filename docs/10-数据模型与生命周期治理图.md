## 核心数据生命周期

### 1. ProxyPool 生命周期

```
创建 (NewProxyPool)
  │  输入: []string (从 proxies.txt 读取)
  │  动作: 随机打乱 (shuffle)
  ▼
运行中
  │  Assign(workerID)   ──▶  从 queue 头部取出分配给 Worker
  │  Release(workerID)  ──▶  放回 queue 头部（优先重用）
  │  Fail(workerID)     ──▶  放回 queue 尾部 + 错误计数 + 重新分配
  │  queue 耗尽        ──▶  复用失败代理（循环）
  ▼
销毁 (超出作用域)
  │  Go GC 自动回收
```

### 2. FilePart 生命周期

```
创建 (DivideFileIntoParts)
  │  输入: totalLength, partSizeBytes
  │  输出: []FilePart
  │  逻辑: [0, partSize), [partSize, 2*partSize), ..., [lastStart, totalLength)
  ▼
发送到 channel
  │  由 main goroutine 发送到 partsChan
  ▼
Worker 消费
  │  从 channel 接收 FilePart
  │  设置 Downloaded = false
  ▼
下载中
  │  调用 DownloadPartialFile(part.Start, part.End)
  │  HTTP Range: bytes=Start-End
  ▼
下载完成
  │  设置 Downloaded = true
  │  .part 文件写入完成
  ▼
合并 (ConcatenateFiles)
  │  按 Number 顺序读取所有 .part 文件
  │  追加写入最终输出文件
  ▼
销毁
  │  删除所有 .part 文件
```

### 3. HTTP 请求/响应生命周期

```
创建 HTTP Client
  │  Transport: 代理配置
  │  跳过 TLS 验证 (InsecureSkipVerify)
  ▼
发送 GET 请求 (带 Range)
  │  通过指定代理
  ▼
收到响应
  │  status 206 Partial Content (正常)
  │  status 416 Range Not Satisfiable (文件大小变化)
  │  status 其他 (错误)
  ▼
流式读取 Body
  │  progressReader: 超时检测
  │  trackReader: 字节计数
  │  写入 .N.part 文件
  ▼
Body 关闭
  │  defer resp.Body.Close()
```

## 数据校验规则

| 数据 | 校验点 | 校验方式 | 失败处理 |
|------|--------|---------|---------|
| proxies.txt | 格式 | 每行非空 | 跳过空行 |
| 代理 URL | 可达性 | HTTP HEAD 探活 | Fail() 换下一个 |
| 目标文件 | Content-Length | HEAD 响应 | 无 Length 则用 416 探测 |
| 分片范围 | Range 合法性 | Start ≤ End < totalLength | 调整末分片范围 |
| .part 文件 | 完整性 | 分片大小匹配 Range 范围 | 重试失败分片 |
| 合并文件 | 大小验证 | 最终大小 = Content-Length | 输出警告，保留文件 |
| .info.txt | 一致性 | 已有文件与当前请求的 Content-Length 对比 | 拒绝继续（文件已变化） |
