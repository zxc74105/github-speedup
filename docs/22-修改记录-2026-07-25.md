# 修改记录 2026-07-25

## 问题清单

### [P1] 代理测速仅有 1 个 active，其余为 silent
- **现象**：`/api/status` 返回 `availableProxies:1, totalProxies:69`
- **根因**：`testSingleProxy()` 硬编码 speed < 1.0 Mbps → silent；测速文件仅 557 字节，单次 `Read` 只能读到 557 bytes，`elapsed` 稍长就低于阈值
- **解决方向**：
  - 使用更大的测速文件（如 1MB），或连续读取累计数据后再计算速度
  - 或降低 silent 速度阈值
  - 或使用测速文件实际大小来校准

### [P2] 代理管理页 — 延迟/速度列不可排序
- **现象**：延迟和速度列没有 `sorter`，无法点击列头排序
- **解决方向**：给 `latency` 和 `speed` 列加上 PySide6 Qt6 原生控件 `sorter` 函数

### [P3] 下载任务页 — 速度列不可排序
- **现象**：速度列没有 `sorter`，无法点击列头排序
- **解决方向**：给 `speed` 列加上 PySide6 Qt6 原生控件 `sorter` 函数

### [P4] 多线程并发下载确认
- **现状**：下载器已实现 `MaxConcurrent` 个 Python 线程 并行下载不同分块，每个 worker 从代理池分配独立代理
- **无需修改**：架构已经是多线程多代理并发

### [P5] handleProxy 不会跳过非 2xx 响应
- **现象**：代理返回 403 时不会尝试下一个代理，直接返回错误给客户端
- **修复**：`proxyRequest` 增加 `resp.StatusCode >= 400` 检查，非 2xx 返回 error，`handleProxy` 自动切换到下一个代理

## 修改方案与实际改动

### 1. 修复代理测速 active 数量（core/proxy_manager.py）
- **实际改动**：累计读取全部响应体数据再计算速度，而不是只读第一个 chunk
- 速度阈值从 1.0 Mbps 调低至 0.1 Mbps
- 延迟阈值从 500ms 放宽至 2000ms
- **结果**：active 从 1 → 62/69

### 3. 下载任务页速度排序（gui/download_page.py）
- `speed` 列添加排序，默认降序

### 4. handleProxy 错误跳过（server/proxy_server.py:proxy_request）
