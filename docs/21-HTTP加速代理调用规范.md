# HTTP 加速代理调用规范

## 概述

本软件提供**两种使用模式**：

| 模式 | 说明 | 谁在用 |
|------|------|--------|
| **主动下载** | 传统下载管理器，GUI 操作，软件自己管理任务和保存 | 终端用户 |
| **被动加速** | HTTP 代理服务，像 `gh.dpik.top` 一样，只加速不保存 | 任意第三方软件/脚本 |

---

## 被动加速模式（核心）

### 原理

```
任何软件/脚本                   本软件 HTTP 服务 (端口 9090)
┌──────────────┐              ┌──────────────────────────────┐
│ curl / wget  │── GET ──→    │  接收请求                     │
│ 浏览器       │   /<目标URL> │  从代理池挑选最优代理          │
│ aria2 / IDM  │              │  将请求原样转发到目标          │
│ Python脚本   │              │  响应流原样返回               │
│ 任何HTTP客户端│←── 响应 ───│  失败自动换代理重试            │
└──────────────┘              └──────────────────────────────┘
```

### 用法

**一行命令加速下载：**
```bash
# curl
curl -O http://127.0.0.1:9090/https://github.com/.../file.zip

# wget
wget http://127.0.0.1:9090/https://github.com/.../file.zip

# aria2 (自带多线程)
aria2c -x 8 http://127.0.0.1:9090/https://github.com/.../file.zip

# PowerShell
Invoke-WebRequest -Uri "http://127.0.0.1:9090/https://github.com/.../file.zip" -OutFile "file.zip"
```

**在浏览器中：**
```
直接在地址栏输入:
http://127.0.0.1:9090/https://github.com/.../file.zip

浏览器自动弹出下载对话框，文件名自动识别。
```

**在下载管理器（IDM/FDM）中：**
```
新建任务 → URL 填入:
http://127.0.0.1:9090/https://github.com/.../file.zip

IDM 接管保存，我们只负责加速传输。
```

**在 Python 脚本中：**
```python
import requests
r = requests.get("http://127.0.0.1:9090/https://github.com/.../file.zip", stream=True)
with open("file.zip", "wb") as f:
    for chunk in r.iter_content(chunk_size=8192):
        f.write(chunk)
```

### 行为规范

| 特性 | 说明 |
|------|------|
| 请求格式 | `GET /<目标URL>` — 把完整 URL 放在路径中 |
| 请求方法 | 支持 GET / HEAD |
| 头部透传 | 所有请求头原样转发（Range / User-Agent / Cookie 等） |
| 响应透传 | Content-Type / Content-Disposition / Accept-Ranges 等全部透传 |
| Range 支持 | ✅ aria2/IDM 可以用多连接分段下载 |
| 断点续传 | ✅ 由调用方管理（带 Range 头请求即可） |
| 文件名 | 由服务器 Content-Disposition 决定，调用方自己处理 |
| 保存位置 | **完全是调用方的责任**，本软件不参与 |
| 失败重试 | 自动换代理重试，调用方无感知（502 前会重试所有可用代理） |

---

### 代理选择策略

```
请求到达
  │
  ├── 从成功记录中取 top 10（成功率最高）
  │       └── 按上次测速延迟排序
  │
  ├── 依次尝试：
  │       #1 延迟最低 → 成功? → 返回
  │       #2 次低     → 成功? → 返回
  │       #3 ...
  │
  └── 全部失败 → 返回 502 Bad Gateway
```

### 配置项

| 项 | 默认 | 说明 |
|----|------|------|
| 启用 | 关 | 开关 |
| 端口 | 9090 | 监听端口 |
| 远程访问 | 否 | 默认仅 `127.0.0.1`，开启后监听 `0.0.0.0` |

## 与主动下载模式的关系

```
┌─────────────────────────────────────────────────────┐
│             Multi-Proxy Downloader                  │
│                                                     │
│  ┌─────────────────┐    ┌─────────────────────────┐ │
│  │  主动下载模式     │    │  被动加速模式            │ │
│  │                  │    │                         │ │
│  │  GUI 操作        │    │  端口 9090 HTTP 服务    │ │
│  │  任务管理        │    │  透明代理               │ │
│  │  进度显示        │    │  不保存文件             │ │
│  │  分片并发        │    │  不限调用方             │ │
│  │  文件合并        │    │  Range 续传             │ │
│  │  成功记录        │    │  零配置使用             │ │
│  └─────────────────┘    └─────────────────────────┘ │
│                                                     │
│  ┌─────────────────────────────────────────────────┐│
│  │  共享部分                                       ││
│  │  代理池 / 成功记录 / 静默机制 / 测速            ││
│  └─────────────────────────────────────────────────┘│
└─────────────────────────────────────────────────────┘
```

两个模式共享同一套代理池和成功记录。主动模式下产生的成功记录会优化被动模式的代理选择。
