# 修改记录 2026-07-25 (第2轮)

## 问题清单

### [P6] 代理类型分类无用
- **现象**：代理管理页有"类型"列（contribute/search/user）和类型筛选下拉框，但所有代理都是同一类 URL-prefix 反向代理，分类无意义
- **解决方向**：删除 `ProxyItem.Type` 字段及相关 UI

### [P7] HTTP 代理调用无运行日志
- **现象**：用户无法知道每次 HTTP API 请求调用了哪些代理、结果如何
- **解决方向**：添加运行时日志文件 `proxy-access.log`，每次启动清空，记录每一步代理使用

### [P8] 浏览器请求路径中 // 被规范化为 /
- **现象**：浏览器将 `http://127.0.0.1:9090/https://github.com/...` 中的 `//` 规范化为 `/`，导致服务收到路径 `/https:/github.com/...`，`handle_proxy` 错误拼接为 `https://https:/github.com/...`
- **修复**：`handleProxy` 中检测 `https:/` 前缀并恢复为 `https://`

### [P9] proxyRequest 未过滤 text/html
- **现象**：CF Workers 代理返回 200 + `text/html` landing page 时直接透传给客户端
- **修复**：`proxyRequest` 增加 Content-Type `text/html` 跳过

## 修改方案与实际改动

### 1. 删除代理类型（前后端）
- **后端** `core/proxy_manager.py`：
  - 删除 `ProxyItem.type` 字段
  - 删除 `load_default_proxies` 中的 `type: "contribute"`
  - 删除 `import_proxies` 中的 `type: "user"`
- **前端** `gui/proxy_page.py`：
  - 删除 `type_filter` state
  - 删除类型筛选下拉框
  - 删除"类型"列

### 2. 添加运行时访问日志
- **新增** `core/logger.py`：
  - `AccessLogger` 类，写入 `proxy-access.log`
  - `init_logger()`：启动时清空文件
  - `log(format, *args)`：追加一行带时间戳的日志
- **修改** `server/proxy_server.py`：
  - 在 `handle_proxy` 中记录请求开始、每个代理尝试、最终结果
- **修改** `core/downloader.py`（可选）：
  - 在多线程下载时记录每个分块的代理分配

### 3. 修复浏览器 URL 路径规范化（server/proxy_server.py:handle_proxy）
- 在 scheme 检查前插入修复逻辑：
  ```python
  if target_url.startswith("https:/") and not target_url.startswith("https://"):
      target_url = "https://" + target_url[len("https:/"):]
  elif target_url.startswith("http:/") and not target_url.startswith("http://"):
      target_url = "http://" + target_url[len("http:/"):]
  ```

### 4. 过滤 text/html 响应（server/proxy_server.py:proxy_request）
- 在 `resp.status_code >= 300` 检查之后增加：
  ```python
  content_type = resp.headers.get("Content-Type", "")
  if "text/html" in content_type.lower():
      raise ProxyError("proxy returned text/html (landing page)")
  ```
